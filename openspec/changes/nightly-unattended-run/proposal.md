## 为什么

需验证夜间无人值守可稳定跑真实多仓库(串行),单个 run 失败不影响其他,并准备 demo 仓库与本项目自跑两类演示案例。

## 变更内容

- demo 仓库:Java17 单模块,埋 5–8 个 sonar 真问题(空指针/资源泄漏/废弃 API/SQL 拼接等)。
- 用 NextMorningstar backend 自跑一轮(真实价值演示)。
- 跑通夜间定时真实触发(21:00),按资源池(默认并发 2)执行。
- 夜间窗口 07:00 硬停在跑的 run(走取消流程 + 删 ai-fix 分支),未启动的明夜重试。
- 修边界:并发调度、超时、取消、单 run 失败隔离。

## 能力

### 修改能力
- `dev-vuln-pipeline`:夜间无人值守稳定执行多仓库,单 run 故障隔离。

## 影响范围

- demo 仓库(新增)。
- 边界处理与稳定性修复。
